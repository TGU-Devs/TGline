# ハーネスの振り返り

このセッションで起きた「同じことを繰り返させないために書き残すべきこと」を洗い出し、
**どこに書くか**まで判定して提案する。

**書き込む前に必ず承認を取る。** 提案を出し、承認された項目だけ反映する。

## 手順

### Step 1: 指摘を洗い出す

このセッションの会話を遡り、以下を拾う。**推測で補わない。実際に起きたものだけ。**

- ユーザーに明示的に訂正・却下された判断
- 「違う」「そうじゃない」「さっき言った」等の否定的な反応
- こちらが自発的に「以後こうします」と述べた改善
- ユーザーが何度も同じ説明をした箇所（＝定義に無いということ）
- 存在しないファイル・パス・API を前提に進めてしまった箇所

該当ゼロなら「反映すべき指摘なし」と報告して終わる。**無理に絞り出さない。**

### Step 2: 一般化する

個別の出来事を、再発を防ぐ「行動を変える一文」に変換する。

| ❌ 出来事のまま | ✅ 一般化した形 |
|---|---|
| 「~/.codex/AGENTS.md を未設定と書いたが実在した」 | 「ファイルやディレクトリの有無を述べる前に、必ず実際に確認する」 |
| 「AGENTS.md の3行を消した」 | 「既存ファイルを書き換えたら `git diff` で削除行を全件確認する」 |

### Step 3: 書く場所を決める

**「誰に効くべきか」で決める。**

| 内容 | 場所 | 効く範囲 |
|------|------|----------|
| チーム共通の事実・規約・アーキテクチャ | `AGENTS.md` | 3人全員 + bot |
| 特定作業の手順 | `.agents/skills/<name>/SKILL.md` | 全員・発火時のみ |
| 個人の好み・作業スタイル | `~/.codex/AGENTS.md`<br>`~/.claude/CLAUDE.md` | 本人のみ・全リポジトリ |

**個人の好みを `AGENTS.md` に書かない。** チーム全員と bot に効いてしまう。

### Step 4: 本当に書くべきか判定する

各項目に以下を問い、1つでも該当したら**書かない**。

- [ ] これを書かなくても、コードを読めば分かるか？ → 書かない
- [ ] 既に同じ趣旨の記述が存在するか？ → 既存を直す（重複させない）
- [ ] これを消してもエージェントは間違えないか？ → 書かない
- [ ] 初めて起きた誤りか？ → **原則2回目から書く。** 1回目はノイズの可能性
      （ただし本番データ破壊など、1回目で致命的なものは即書く）

> 「2回目から」は公式の規定ではなく経験則。判断に迷ったら書かない側に倒す。

### Step 5: 剪定する（重要・省略しない）

**追加だけでは必ず劣化する。** 肥大化した定義ファイルは、書いてある指示を無視させる。

`AGENTS.md` と関連スキルを読み、以下を削除候補として挙げる。

- コードや `README` を読めば分かる内容
- 既に守られていて、書かなくても崩れない内容
- 古くなった記述（消えたファイル、変わった構成を指している）
- 同じことを言っている重複行

削除は追加と同じく**承認を取ってから**行う。

### Step 6: 提案を出す

以下の形式で出力し、**ここで止まる。**

```markdown
## 振り返り結果

### 追加提案
1. **{一般化した一文}**
   - 発端: {実際に何が起きたか。1行}
   - 場所: {ファイルパス}
   - 理由: {これで何が変わるか}

### 削除提案（剪定）
1. **{削除する行}** — {なぜ不要か}

### 見送り
- {拾ったが書かないと判断したもの}: {理由}
```

承認された項目のみ反映する。反映後は `git diff` で**削除行を全件確認**し、意図しない消失がないことを示す。

## やってはいけないこと

- 指摘が無いのに項目をでっち上げる
- 「丁寧に」「適切に」のような、行動が変わらない文言を足す
- ロールプレイ（「あなたは熟練の〜」）を足す
- 承認前に書き込む
- 剪定を飛ばして追加だけする
